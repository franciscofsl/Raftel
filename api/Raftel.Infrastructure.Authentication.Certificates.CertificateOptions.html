Remarks

Bound from the Authentication:Certificates configuration section and then from the configureCertificates callback of AddRaftelData.

Each certificate is loaded either from the X.509 store by thumbprint or from a PKCS#12 (.pfx) file. Set one source per certificate, never both. Keep certificate passwords in a secret store (user secrets, environment variables, a vault), never in a committed appsettings.json.

When no certificate is configured, ephemeral development certificates are generated only in the Development environment. In any other environment the application fails at startup until both certificates are configured, because development certificates are not shared between instances and tokens issued by one replica would not validate on another.
